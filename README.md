# ЭПУ · Диспетчер ППР

Прототип веб-инструмента для планирования планово-предупредительных работ (ППР) и учёта дефектов на электропитающих установках (ЭПУ) оборудования связи.

## Состав репозитория

- `index.html` — рабочий инструмент (дашборд). Один самодостаточный файл: HTML + CSS + JS, без сборки и внешних зависимостей.
- `TZ_AI_dispatcher_PPR.docx` — техническое задание на внедрение ИИ-диспетчера (для справки/согласования).

## Как запустить

**Локально:** просто откройте `index.html` в браузере (двойной клик или перетащить в окно браузера).

**Через GitHub Pages:**
1. Зайдите в репозиторий → `Settings` → `Pages`.
2. В разделе `Build and deployment` выберите `Deploy from a branch`.
3. Ветка — `main` (или та, куда загружены файлы), папка — `/ (root)`.
4. Сохраните — через 1–2 минуты сайт будет доступен по адресу вида `https://<ваш-логин>.github.io/<репозиторий>/`.

Файл называется `index.html`, поэтому GitHub Pages подхватит его автоматически как главную страницу — переименовывать не нужно.

## Важно про данные

Инструмент хранит все записи (оборудование, дефекты) **в localStorage браузера посетителя** — без сервера и базы данных. Из этого следует:

- Данные видны только на том устройстве и в том браузере, где их вносили; между разными людьми/устройствами они не синхронизируются.
- Очистка кэша/данных сайта в браузере удалит записи.
- Это подходит для демонстрации и черновой работы одного пользователя, но **не подходит** как многопользовательская система — для реального внедрения в компании нужен бэкенд с базой данных (см. раздел 7 ТЗ, «Требования к данным и архитектуре»).

## Доработка

Это черновик. Наиболее вероятные следующие шаги:
- Подключить реальный бэкенд (база данных + API) вместо localStorage, чтобы данные были общими для всех диспетчеров.
- Загрузить фактический реестр объектов и оборудования вместо демо-данных.
- Настроить нормативную периодичность ТО под ваши регламенты.
